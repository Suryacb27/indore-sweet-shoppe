## Overview

**Indore Sweet Shoppe** is a premium Indian sweets e-commerce storefront built with Next.js 16 App Router. It allows customers to browse products by category, add items to a persistent server-side cart, place orders, and manage their profile. Admins have a protected dashboard for managing products, categories, and orders. Authentication and all data persistence is handled entirely by Supabase.

## Data Flow

### Customer Purchase Flow

```
1. Browse /products → Supabase query (products + categories)
2. Click product → /products/[id] → Supabase query (product + inventory)
3. Add to cart → addToCart() server action → upsert to cart_items
4. View /cart → server fetch cart_items joined with products
5. Place order → createOrder() → Supabase RPC create_order_transaction
6. Clear cart → delete cart_items for user
7. Redirect → /checkout/success?orderId=xxx
```

### Auth Flow

```
1. Signup → signup() action → supabase.auth.signUp() + profiles INSERT (role: customer)
2. Login → login() action → supabase.auth.signInWithPassword()
3. Session → stored in cookies, refreshed on every request by middleware
4. Admin guard → middleware checks profile.role === 'admin' on /admin/* routes
5. Logout → /api/auth/signout POST route → supabase.auth.signOut()
```

## Middleware & Security

- `middleware.ts` (project root) calls `updateSession` from `lib/supabase/middleware.ts`
- **Route protection**: Any `/admin/*` request checks auth + profile role server-side
- Double-guarded: middleware redirects + `app/admin/layout.tsx` also performs server-side role check
- `adminBootstrap` action self-disables once any admin exists in `profiles`

## Conventions

- **Naming**: PascalCase for components, camelCase for actions/functions, kebab-case for routes
- **Structure**: Feature-grouped — all auth in `components/auth/`, all admin in `components/admin/`
- **Server/Client boundary**: Server Components for data fetching, `"use client"` only where interactivity needed (forms, mobile menus). Server actions marked `"use server"`.
- **Styling**: Tailwind CSS v4 with custom CSS variables (`--font-sans`, `--font-serif`, `bg-primary`, etc.)
- **Error handling**: Server actions return `{ error: string }` objects or throw errors; forms handle display client-side
- **Testing**: No tests present
